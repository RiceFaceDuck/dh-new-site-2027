## 2. ขั้นตอนและแนวทางปฏิบัติการทดสอบจริง (Real-World Testing Procedure)

เมื่อได้รับมอบหมายให้ **"ทดสอบสถานการณ์จริงๆ (Real Situation)"** หรือมีการสั่งให้ **"กบแดง" (ai.manager@dhnotebook.com)**, **"ไม้เขียว" (antigravity.staff@gmail.com)**, หรือ **"ม้าดำ" (ai.tester@dhnotebook.com)** ช่วยทดสอบจริง ให้ยึดหลักการทำงานและจำลองสถานการณ์ E2E ดังนี้อย่างเคร่งครัด:
1. **End-to-End Simulation (E2E):** ทำการทดสอบสถานการณ์จริงในบทบาท **[พนักงานจริง]** หรือ **[ผู้ใช้งานจริง]** ด้วยการจำลองเข้าใช้งานหน้า UI จริง (เช่น ผ่าน Browser / UI Automation) ไม่ใช่อ่าน code หรือแก้ไข code (เนื่องจากไม่ได้ทำงานในฐานะนักพัฒนาในขณะทดสอบ)
2. **No Data Mocking (ห้ามจำลองข้อมูลเองเด็ดขาด - Strict Directives):** ห้ามเขียนสคริปต์แทรกแซง ล้วง หรือจำลองป้อนข้อมูลดิบลงฐานข้อมูล (Firestore/Database) โดยเด็ดขาดไม่ว่าในกรณีใดๆ (เช่น ห้ามใช้สคริปต์หลังบ้านเขียน Order จำลอง, ห้ามตัดสต๊อกจำลอง) ทุกอย่างในขั้นตอน E2E จะต้องเป็นการทำรายการจริงผ่านหน้าต่าง UI ด้วยพฤติกรรมของผู้ใช้ออร์แกนิก 100% เท่านั้น!
3. **Production Ready State & Organic Learning:** ให้ถือว่าข้อมูลสต๊อกและข้อมูลออเดอร์ต่างๆ จะถูกเคลียร์และอัปเดตของจริงเมื่อระบบเปิดให้บริการ (Launch) ดังนั้นการทำงานของ AI จึงควรโฟกัสที่ความพร้อมของ "ระบบและการแสดงผล (Logic & UI)" ไม่ใช่ข้อมูลจำลอง และปล่อยให้ระบบเรียนรู้และบันทึกประวัติการทำงานจากการใช้งานจริง
4. **Screenshot Capturing on Issues & Improvements:** ทุกครั้งที่จำลองใช้งาน E2E แล้วพบจุดบกพร่อง บั๊ก ข้อผิดพลาด หรือพบส่วนงาน/หน้าจอที่คิดว่าสามารถนำไปพัฒนา/ปรับปรุงเพิ่มเติมได้ **จะต้องบันทึกภาพหน้าจอ (Screenshot) ของสถานการณ์ดังกล่าวไว้เสมอ** เพื่อแสดงเป็นหลักฐานและนำมารายงานผลให้ผู้ใช้ทราบ
5. **No Immediate Fixes during Testing:** ห้ามทำการแก้ไขโค้ดหรือระบบทันทีเมื่อเจอปัญหาในระหว่างการทดสอบ ให้รวบรวมรายละเอียดปัญหาและข้อเสนอแนะ พร้อมระบุรูปภาพหลักฐาน บันทึกแยกเก็บลงในไฟล์ข้อผิดพลาด [.agents/memory/ISSUES.md](file:///c:/DH%20Notebook/Management%20System/.agents/memory/ISSUES.md) เพื่อรอการวางแผนและดำเนินการแก้ไขในรอบงานถัดไป
6. **Real Testing Execution (การทดสอบจริงแบบ 100%):** เมื่อได้รับคำสั่ง "ทดสอบจริง" เอเจนต์จะต้องทำการ "เข้าใช้งานจริง" เสมือนพนักงานใช้งานผ่านหน้า UI เท่านั้น ห้ามใช้วิธีลัดด้วยการอ่านโค้ด หรือแอบแก้โค้ดหลังบ้านเพื่อจำลองข้อมูลเด็ดขาด! หากพบปัญหาจากการทดสอบ ให้รวบรวมมาบันทึกใน ISSUES.md และรายงานผู้ใช้เท่านั้น โดยห้ามสร้างข้อมูลจำลองเพื่อข้ามขั้นตอนโดยเด็ดขาด
7. **Firebase Emulator Testing Rule (การทดสอบผ่าน Emulator):** การทดสอบและการรันระบบ E2E ทั้งหมดจะต้องดำเนินการผ่าน Firebase Local Emulator เสมอ โดยใช้พอร์ตมาตรฐาน: Auth (`9099`), Firestore (`8080`), Storage (`9199`) และ Emulator UI (`4000`) 
   - ไฟล์ควบคุมและเปิด-ปิดการใช้งาน Emulator คือ `.env` และ `.env.development` (ด้วยตัวแปร `VITE_USE_FIREBASE_EMULATOR=true`)
   - ไฟล์โค้ดตั้งค่าการเชื่อมต่อของแต่ละโปรเจกต์อยู่ที่:
     - หน้าบ้าน: [dh-frontend/src/firebase/config.js](file:///c:/DH%20Notebook/Management%20System/dh-frontend/src/firebase/config.js)
     - หลังบ้าน: [dh-backoffice-react/src/firebase/config.js](file:///c:/DH%20Notebook/Management%20System/dh-backoffice-react/src/firebase/config.js)
     - แอปพนักงาน: [dh-staff-app/src/firebase/config.js](file:///c:/DH%20Notebook/Management%20System/dh-staff-app/src/firebase/config.js)
   - ห้ามทำการทดสอบหรือ E2E บัญชีทดสอบ (ม้าดำ, กบแดง, ไม้เขียว) ตรงไปยัง Production Databaseเด็ดขาด
8. **AI Self-Verification for Screenshots (การตรวจสอบภาพด้วยตาตัวเอง):** ห้ามด่วนสรุปผลลัพธ์การทดสอบและรายงานผลสำเร็จ หากยังไม่ได้ใช้คำสั่ง (Tool) `view_file` เปิดตรวจสอบไฟล์ภาพหน้าจอ (Screenshot) ที่แคปเจอร์มาด้วยตัวเองก่อนเสมอ! เพื่อเป็นการตรวจสอบซ้ำและยืนยันว่าหน้าจอที่จับภาพมานั้นโหลดเสร็จสมบูรณ์, เปลี่ยนหน้าจอสำเร็จ, และแสดงผลลัพธ์ตามเป้าหมายจริงๆ (ไม่ใช่การด่วนสรุปจากข้อความ Log หรือหน้าที่ยังโหลดค้างอยู่)
